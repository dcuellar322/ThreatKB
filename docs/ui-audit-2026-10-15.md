# Forms, data presentation and browser audit — 2026-10-15

The counts below describe this audit pass. Current maintenance verification,
dependency totals and integration limits are in [verification.md](verification.md).

This pass reviews the running application against upstream `rc` and the preceding capability audit. Browser mutations use `threatkb_browser_qa`, its separate file/content stores and Redis queue. Main development data is preserved.

## Changes

- Signature forms separate detection logic and MITRE ATT&CK fields. Configuration checkboxes sit in an Options group instead of interrupting the field grid. Dialog titles identify the definition being edited. Multiline fields use the full grid width. Indicators, tasks and release creation use compact dialogs; YARA/YAML/code editors retain wider space.
- Action rows have consistent spacing and alignment. Import actions no longer stretch across the entire panel. File selection uses a styled, keyboard-operable control. Sample selection supports removing a file and clears results when its input changes; scanning multiple selections explicitly says “Scan first sample.”
- Disclosures share a chevron, hit area, hover/focus treatment and expanded boundary. Configuration tabs scroll horizontally on narrow screens. Dialog headers and primary actions remain available while the body scrolls. On mobile, secondary record controls expand under **Record actions**, giving the form more room; the desktop controls remain visible.
- Attached sample rows now align checkbox, icon, filename/hash and download horizontally. This fixes a generic label style that had stacked them vertically. Sample and goodware test actions share a row; match-history badges no longer grow into oversized columns.
- File test results have their own bounded, keyboard-focusable scrolling region and sticky headers. Long command/output text remains readable without enlarging the whole dialog. Job results use labeled values, localized timestamps, status chips and readable user identities; job inputs remain available in a disclosure. Import outcomes use Imported/Retired/Duplicates/Errors counts instead of a raw JSON summary.
- Release tables again show test/production channel, signature/IP/domain counts and creator. Activity tables again show the analyst. The restored columns support the appropriate server sorting. Admin Git exports are available on Import & export as well as their prior Configuration location.

The black/white/red theme remains. This pass adds no promotional UI copy or dependencies.

## Correctness fixes found while testing

| Failure | Correction and browser verification |
|---|---|
| A pending search cleared selected IDs after a bulk dialog opened, producing “Edit 0 records.” | Selection is disabled while a query is pending; opening the dialog snapshots its IDs. Verified with an artificially delayed query and all four artifact bulk editors. |
| Ctrl+S omitted an unfinished tag or MITRE input. | Pending chip text commits before form submission. Saved/reopened the record and checked the tag persisted. |
| A successful save could leave the record ID in the URL after closing its dialog. | Unmount the dialog guard before navigating after save/close. Verified immediate reopening and permalink behavior. |
| A different permalink could reuse the previous record's form state. | Key artifact editors by record identity. Verified switching between two signature IDs on the same page. |
| Browser navigation could discard configuration or Git/YAML drafts. | Shared dialog guards check the whole dialog stack and unfinished chip text during navigation and unload; Ctrl+Q also protects pending chip input. Confirmed/discarded tab navigation closes the old definition form. Cancel preserves it. Nested dialogs preserve their parent and release scroll locks correctly. |
| Inactive records still offered Deactivate. | Offer restore instead. Verified deactivation/restoration of signatures, IPs, domains and tasks. |
| Configuration tab loads could overwrite a newer request. | Abort outdated requests and reject stale responses; the selected tab is reflected in the URL and survives reload. |
| Source validation was only visible after a failed request; editing a source name silently created another monitor. | Validate name/delay bounds in the form and keep an existing source's identity read-only. Verified invalid values are rejected before submission. |
| Refresh did not fetch current configuration, following or access-key data. | Wire view versions through those pages; verified actual network responses on refresh. |
| An old success timer could dismiss a newer message. | Cancel the prior timer when replacing a notification. |
| Git saves/creation and key actions could be repeated while a request was pending. | Guard pending actions and surface busy state; retain errors. Access-key revocation supports cancellation/confirmation. |
| Home/End in dropdown search moved options instead of the text cursor. | Preserve text editing; arrow navigation skips disabled choices and filtered results scroll into view. Verified no-match feedback and Escape preserving the dialog. |

## Queued-save follow-up

Signature creation, YAML editing, and repository-settings saves now show their
queued/validating state inside the dialog and display the resulting Git commit
only after the worker succeeds. Pending editors are read-only, prevent duplicate
submissions, and offer Continue in background. The pending job/editor survives a
tab reload and is restored on returning to Detection as code. Failures preserve
the draft and offer a confirmed Reload latest action.

Chromium exercised real HTTP 202 saves and the local Celery/Redis worker, including
creation, editing, settings, worker downtime/restart, reload recovery, continuing
to Background jobs, invalid-YARA failure without a source/revision change, and a
409 conflict after a real concurrent commit. Observed save responses were 129–299
ms on the development catalog; worker completion remains asynchronous. Desktop
and 390px mobile screenshots were reviewed, with no horizontal overflow. Console
messages were the expected initial unauthenticated 401 and deliberate stale-save
409; no JavaScript exceptions were observed. Evidence is under ignored
`output/playwright/maintenance-2026-10-15/content-save-*.png` and
`content-settings-committed.png`.
