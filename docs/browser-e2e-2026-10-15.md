# End-to-end browser verification — 2026-10-15

This pass exercises the running application in Chromium against real Flask, MySQL,
Redis and Celery services. Mutating checks use `threatkb_browser_qa`, a separate
instance directory, Git content repository and Redis database 1. The main local
application uses MySQL `threatkb` and Redis database 0. Destructive checks, account
changes, new signatures and synthetic pagination rows are confined to QA.

The final main-app smoke test visits all 18 pages using their navigation links at
1440 × 1000 and 390 × 844, checks page headings, mobile-menu dismissal and document
overflow, and captures all 36 views. Browser artifacts and journey results are
local under `output/playwright/e2e-2026-10-15/`; `index.html` is the screenshot
index and `results.json` records the accepted checks. Earlier failing runs are
superseded by the focused verification listed below.

- All **80 backend tests pass** locally, including new metadata, task-tag,
  task-permission and query regression cases. The frontend type check and
  production build pass.
- Final targeted browser reruns report no uncaught JavaScript errors. Expected
  negative cases return validation/auth/permission/not-found/gate errors and keep

  MySQL database. Main web, worker and scheduler processes run the current code.

  compatibility or exhaust every possible input combination.
- Vendor DFI remains skipped under the user's authorization. Archive deletion
  fixtures verify the UI/storage workflow without asserting proprietary extraction.
- Production promotion correctly rejects releases without production telemetry and
  the required observation period. Successful local testing publication is verified;
  receiving-system deployment and external production telemetry remain operational
  acceptance items in [verification.md](verification.md).
